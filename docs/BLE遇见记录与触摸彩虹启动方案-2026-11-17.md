# BLE 遇见记录、触摸与彩虹启动方案

日期：2026-11-17。状态：用户已确认产品流程；本文仅实现分析，尚未开发或烧录。

## 最新规则

| 阶段 | 正式版 | 当前 COM7 / COM25 测试 |
|---|---|---|
| 靠近 | BLE 互相发现、读取公开玩偶名片，各自在本地记录新玩偶，不自动说话 | 相同 |
| 触发 | 两台都触摸确认 | 只需 COM7 触摸，COM25 无触摸按键，以测试白名单自动加入 |
| 视觉反馈 | 双方确认后，两台 RGB 各闪一轮彩虹灯 | 仅 COM7 闪一轮，COM25 不增加闪灯要求 |
| 开始 | 两台 ready、所需彩虹动画完成后开始轮流对话 | 相同，但反馈设备仅 COM7 |

COM25 的免触摸是显式测试策略，不能把“没有触摸就默认同意”作为正式规则。此前“单台触摸适用于正式版”的讨论由本方案替代。

## 靠近先记住

- 广播筛选服务 UUID、版本和能力；连续多次收到信号才列入附近候选，RSSI 不作为精确测距。
- 广播用于发现，短连接 GATT 交换公开名片：稳定随机 social_id、nickname、能力和名片版本。身份不使用主人账号、手机号或登录令牌；可公开的星座/MBTI按后续名片契约决定。
- 稳定 social_id 用于判断以前是否遇见；轮换的 discovery_nonce 只标识本次发现，不能用它判断“新玩偶”。相同昵称也不能当同一设备。
- 稳定的已遇见记录写 NVS，附近状态/RSSI/last_seen 单调时钟留 RAM。首次记录、交流完成时更新，避免每个广播包写 Flash。建议首版有界 32 项，容量与淘汰策略待实测。
- 重启保留“曾遇见”，但必须重新收到 BLE 数据才能认定仍在附近。无网络可记录遇见，不能自动补播后来恢复网络的对话。
- 本地遇见不是云端好友。旧方案“同意前只做匿名发现”调整为可先读取、缓存公开玩偶名片；会话授权、主人资料和云端社交事件不在靠近阶段交换或生成。

## 触摸与开始门槛

现有板型 TouchLoop 只检测并打印按下/松开，没有接入唤醒或创建社交会话。有效触摸电极要按两块实物确认，不能沿用旧板某通道损坏的结论。

建议新增 SocialCoordinator，统一接收 BLE 候选与触摸事件：

1. 有唯一附近候选、设备空闲时，稳定触摸触发一次确认；需松开后再触发，带去抖和冷却。
2. 正式模式分别记录本次、绑定对端的两侧触摸，均有效才准备。建议约 30 秒确认窗口，超时、离开或忙碌撤销，具体参数待验证。
3. 测试模式仅 COM7 触摸生效；COM25 在白名单匹配且空闲时返回 test_auto_accept，不伪造真实触摸证明。
4. 无附近玩偶保留普通触摸行为；多候选首版不随机选人。与既有“触摸进 K230 全功能模式”的待开发需求共用事件路由，避免一次触摸被两个模块同时消费。

## RGB 反馈

- 正式双确认后两台各闪一轮，测试仅 COM7 一轮；建议约 1 秒，最终时长/亮度目视确认。
- 通过 LedMoodController 协调现有六颗灯，不创建第二个 GPIO3/RMT 驱动。动画完成恢复之前的灯光状态，包括关灯状态。
- 定时器或灯光任务非阻塞推进，完成产生 feedback_done。取消时使旧回调失效，不能让迟到的回调启动已取消会话。
- 所需设备 feedback_done 与两台 ready 都满足后才发首段 TTS；云端就绪不能抢在彩虹完成前说话，彩虹完成也不能绕过对端离线。

## 唤起第二台与云端衔接

BLE START_PREPARE 携带本次 encounter/session nonce、双方角色、策略版本和有效期。接收方校验附近候选、触摸策略与忙碌状态，再由各自固件主动打开云端连接，无需假设语音 WS 常驻。

两台走社交专用入场，不经过普通唤醒词开场白和 ASR/LLM：

```text
BLE 发现 → 交换公开名片 → 本地记新玩偶
                         ↓
正式双触摸 / 测试 COM7 触摸
                         ↓
BLE 协调准备 → 所需 RGB 彩虹一轮
                         ↓
双方各自打开 WS → 云端幂等匹配入场
                         ↓
双方 ready + 反馈完成 → COM25 雾星与 COM7 轮流对话
```

同一次双方请求只分配一 room_id，身份取认证连接；固件不能任意指定其他在线设备发起对话。临时 BLE 发起方选举仅用于去重，不能代替认证。

已验证的双真 speaker/actor 身份映射、停麦、逐段 played 回执和 500ms 间隔可复用。仍需设计设备级入场、双方匹配、反馈门槛契约，不能把运维测试服务的凭据放进固件。

## 异常与验收

- 靠近未触摸：仅本地记录，不说话、不建房间。
- 正式只摸一台：等待另一台，超时取消；测试 COM7 摸一次则 COM25 加入，只有 COM7 彩虹。
- 同时/重复触摸：一次房间、每台所需动画仅一次，不能重播。
- 对端离开、无网络、忙于普通对话/音乐/拍照/OTA：不抢占，不强行开聊。
- 历史见过但不在附近：不能隔空触发。
- 对话期间停普通收音；任一方退出/断线/超时，停止后续轮次并恢复灯光和普通模式。

实现顺序：先 BLE 名片和本地遇见表；再接 COM7 触摸与一次彩虹；再完成 BLE 唤起、按需 WS 入场和双真调度；最后扩展正式双触摸策略。各阶段均测重启、去重、对端离开、断网和取消。

两块均已确认 S3，但当前未启用 BLE。Wi-Fi/BLE 共用射频，要在语音、眼睛、灯与 USB 相机场景下验证共存，不能仅以扫描成功验收。
