# COM25 / COM7 BLE 偶遇与受控对话设计草案

日期：2026-11-17。状态：分析草案，未冻结接口，未实现 BLE。双实体机对话内容见 backend docs/双机对话脚本-COM25雾星-COM7-2026-11-17.md。

## 硬件核实与已完成部分

- COM7 与 COM25 均由 esptool 识别为 ESP32-S3，16MB PSRAM，具备 BLE；不是 P4+C6 路径。COM25 只做芯片探测和复位，没有烧录。
- COM7 当前配置 CONFIG_BT_ENABLED 未启用。现有 BluFi 是配网，不能当成设备社交；建议社交独立使用 NimBLE，并与 BluFi/配网模式互斥管理生命周期。
- 一真一模拟的四轮台词、云端轮次和 COM7 播放排空回执已通过。BLE 只需要交换发现/同意/身份授权数据，语音仍走各自 Wi-Fi 到小智服务。

## 建议分两阶段实施

先开发手动选择两台在线机器的测试房间，跑通八段双真回执；这仅是运维联调入口，不作为产品配对方式。再接 BLE 自动发现、双方主人同意及身份交换。最终产品仍是自然偶遇，不能用手动选择取代原需求。

## BLE 分工与发现包提案

两台均低频广播并被动扫描；空闲时发现，播放/拍照/OTA时降低或暂停扫描。ESP32-S3 的 Wi-Fi 和 BLE 共用射频，必须通过真实音频负载校准，不能因为分别能用就登记并发已验收。

建议自定义一个 128-bit 服务 UUID，采用 Service Data 128-bit AD（0x21），避免冒用厂商 company ID。传统 31 字节广播内只放：Flags AD 3 字节 + Service Data AD 28 字节，其中 UUID 16 字节、协议版本 1 字节、能力位 1 字节、discovery_nonce 8 字节，另 2 字节为 AD 长度/类型。总计 31 字节，不再额外广播设备名、完整服务 UUID 列表或身份。字节序和 UUID 值在实现前冻结并做编码测试。

- 不广播 MAC、宠物名、主人信息、MBTI、人设或可解析身份 token。BLE 链路地址也需启用地址隐私，不能只隐藏 payload 却固定暴露地址。
- discovery_nonce 定期轮换；候选需多次收到稳定信号，设置去重和冷却。RSSI 只用于候选筛选，不等于精确距离。
- 初始广播间隔可从约 1 秒起测；扫描窗口/间隔按音频、Wi-Fi、USB相机负载测后决定，不在本草案承诺功耗或距离。

## 双边同意与 GATT 交换

状态建议：idle → discovered → awaiting_local_consent → awaiting_peer_consent → exchanging_grants → reporting → ready → playing → finished/cancelled/expired。拒绝或超时不换身份 token、不上报可识别偶遇、不建好友。

1. 发现后用匿名 nonce 的确定性比较选择临时连接发起方，避免两台同时反复连接；这只是去重，不是身份认证。
2. 短连接 GATT 先交换版本/双方 nonce 和同意状态。每台只在本地主人确认后发 consent；未收到双边同意之前不得发身份授权。
3. 双边同意后交换短期、会话绑定的授权 token；种子 social_secret 绝不在 BLE 发送。后端需校验有效期、双报告互相对应、nonce/用途绑定和防重放。具体 token 签发/派生契约需要修改 backend docs/06 后实现；不能只用明文固定 MAC，或把通用设备登录令牌拿来当社交 token。
4. GATT 协议要支持默认 MTU 下分片、序号、长度上限、重传去重、确认和超时；不假设已协商大 MTU。协商连接加密与应用授权的边界需在冻结时明确。
5. 交换完成即断 BLE，两台各自上报云端。云端匹配后排台词，再用设备自己的下行连接播放。BLE 不搬运 Opus 音频。

## 必须补的云端/固件接口

- 现有 social_test 仅单真+模拟：扩展为双方均 authenticated/ready 的 actor 映射；speaker->device_uid 由云端绑定。所有回执均来自各自连接，重复/乱序不能跨设备解锁。
- 正式 backend 仍需社交开启开关、授权凭证、双方报告匹配、内容计划与终态；草案既有报告端点尚未实现。测试内存房间不作为正式事件存储。
- 空闲语音 WS 已断开时的传输仍未解决：短期可做本地偶遇确认后按需打开语音 WS，增加服务端专用社交握手；对比独立 MQTTS 控制通道后再冻结，不借本次在线测试宣称 E11 完成。
- 播放期间双方停普通收音；任一方取消/断线必须让双方收尾并恢复。真人语音插话需独立验收，初期使用 BOOT。

## 验收顺序

1. 双真在线固定内容、八条真实播放回执、结束后普通对话恢复。
2. 仅广播/扫描：两台发现、过滤陌生 UUID、nonce轮换与去重，同时验证语音/眼睛/灯。
3. 本地双边同意：拒绝、超时、单边同意均不交换身份。
4. GATT：分片重传、角色冲突、过期凭证、防重放、断连恢复。
5. 完整偶遇：双报告匹配、内容生成、轮流播放、掉线收尾；蓝牙/Wi-Fi共存负载至少覆盖连续对话与拍照。
